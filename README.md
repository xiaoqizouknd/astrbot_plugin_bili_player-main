# bili播放器

面向 AstrBot 的 Bilibili 点播插件：搜索并锁定具体分 P，按意图发送视频、可播放音频或音频文件；平台不适配时自动改发文件。

## 功能

- **自然语言点播**：`我要听晴天`、`我要看晴天`。LLM 提取条件，只允许从插件当次返回的候选中选择。
- **显式搜索**：`搜索歌曲 <关键词>` / `搜索视频 <关键词>`（别名：`点歌`、`来一首`、`bili`、`看视频`），展示最多 10 条候选，用户回复序号交付。
- **换一批**：候选列表末尾提示“想看更多结果：回复‘换一批’”；回复 `换一批`/`换一首`/`再来一批` 自动复用上次搜索并翻页，无需重发关键词。
- **精确视频**：识别 AV/BV 号、`bilibili.com/video/...` 链接以及 `b23.tv`/`bili2233.cn` 短链接，列出全部分 P。
- **可选登录**：匿名即可搜索播放；登录仅用于提升受限内容可用性。
- **防风控**：内置 API 并发上限、失败指数退避冷却、风控码免重试、视频详情短时缓存与每会话限流（搜索 6 次/分钟、交付 3 次/分钟），异常流量不会连累整台机器人。

## 安装

1. 安装 `ffmpeg`，确保在 AstrBot 进程的 `PATH` 中。
2. 可选：`python -m pip install "qrcode[pil]"`，用于 WebUI 扫码登录。
3. 在 AstrBot 插件仓库中填入：

```text
https://github.com/57Darling02/astrbot_plugin_bili_player
```

运行要求：AstrBot `>=4.26,<5`、Python `>=3.10`、可访问 Bilibili。自然语言点播需要模型支持工具调用；建议 Provider 工具超时直听 ≥ 300 秒、直接视频 ≥ 900 秒，并关闭 `provider_settings.show_tool_use_status` 与 `show_tool_call_result`，避免工具过程文字出现在聊天里。

## 配置

在 AstrBot WebUI 的插件详情中打开原生配置面板：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 默认媒体类型 | 默认视频，可发送音频 | 用户只说“播放/来一首”等未明确媒体类型时使用；“仅视频/仅音频”会拒绝相反类型的显式请求 |
| 音频形式优先级 | 优先语音，超限发文件 | 语音 ≤ 15 分钟、25 MiB；选择文件优先则直接发音频文件 |
| 交付限制 | 语音 15 分钟/25 MiB，视频 50 MiB，音频文件 50 MiB | 可在安全范围内调整；时长 0 表示不限，超时与并发仍固定 |

实际交付时，插件会先发送“正在准备音频/视频，请稍候。”提示，再下载、转码并发送媒体；媒体成功送达后保持静默，不再追加确认文字。

保存后 AstrBot 会自动重载插件。登录状态、二维码与 `ffmpeg` 健康检查在插件 Page“账号与运行状态”中查看。

## 使用

直接说意图：

```text
我要听周杰伦的晴天     # 发送可播放音频
我要看晴天             # 发送视频
播放晴天               # 按“默认媒体类型”配置发送
下载晴天               # 展示候选，确认后下载音频文件
点歌 晴天              # 等同“搜索歌曲 晴天”
看视频 BV1xxxxxxxxxx   # 等同“搜索视频”
我要看 https://b23.tv/xxxx  # 短链接自动展开为精确视频
```

或者显式搜索，再回复序号：

```text
搜索歌曲 晴天
1          # 发送第 1 项的视频
1 音频     # 播放第 1 项
1 音频下载 # 下载第 1 项
换一批      # 复用上次关键词，翻页展示新候选
取消       # 结束选择
```

候选列表的回复语法会随配置变化：例如“仅音频”时，裸序号直接播放或发送音频文件。

精确视频会列出全部可交付分 P：

一条消息混入多个 AV/BV 时，插件不会猜测任务边界，而是把整段消息作为一个模糊关键词搜索，并强制展示候选让你自行选择。

```text
搜索视频 BV1xxxxxxxxxx
搜索歌曲 https://www.bilibili.com/video/BV1xxxxxxxxxx/
```

## 交付边界

| 意图 | 交付 | 限制 |
| --- | --- | --- |
| 听 / 播放 | 语音或音频文件 | 语音 ≤ 15 分钟、25 MiB；超限或平台不支持时改发文件 |
| 看视频 | 视频 | ≤ 50 MiB；平台不支持时改发文件 |
| 未明确媒体类型 | 按插件配置 | 同一候选锁定为 `bvid:cid`，不换歌、不换分 P |
| 下载音频 | 音频文件 | ≤ 50 MiB、不限时长；必须用户确认 |

候选默认显示时长与标题（超出 24 字截断）；开启 `show_uploader` 配置后列表附带 up 主名（最多 20 字截断），便于识别翻唱版本。超过 15 分钟的音频标记“音频仅可下载”。`weixin_oc` 平台的语音会直接以文件交付。

每会话限流：搜索 6 次/分钟、媒体交付 3 次/分钟，超限会提示等待秒数。当 B 站风控拦截（-352/-412 等）或连续请求失败时，插件会进入指数退避冷却，冷却期内不再打点，稍后自动恢复。

## 管理与安全

插件 Page“账号与运行状态”仅 Dashboard 主账号可访问：

- 查看 `ffmpeg` 健康状态。
- Bilibili 扫码登录、取消或退出；退出只删除本地凭证。
- 扫码不可用时，可在页面直接粘贴浏览器 Cookie 手动登录：凭证会立即校验，无效会被拒绝。
- Cookie 只存插件数据目录 `accounts.json`（`0600`），不进入聊天、日志或 WebUI。
- 媒体文件发送后立即删除；无播放历史、收藏和缓存。

### 手动登录与 accounts.json

扫码登录不可用时（如 B 站扫码接口异常），两种手动方式任选：

1. **WebUI 粘贴 Cookie**：打开插件 Page“账号与运行状态”，展开“手动粘贴 Cookie 登录”，粘贴浏览器 `Cookie` 请求头的完整内容（须含 `SESSDATA`），点击“导入并校验”。
2. **直接写 accounts.json**：在插件数据目录（AstrBot 的 `data/plugin_data/astrbot_plugin_bili_player/`）创建 `accounts.json`，格式如下：

```json
{
  "version": 1,
  "bilibili": {
    "cookies": {
      "SESSDATA": "...",
      "DedeUserID": "...",
      "bili_jct": "..."
    },
    "saved_at": 0
  }
}
```

`cookies` 字段名与值需与浏览器一致（含 `SESSDATA`、`DedeUserID`、`bili_jct`）。写入后重启插件或重载页面即可生效。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 提示缺少 ffmpeg | `ffmpeg -version`，确认 PATH |
| 无法生成二维码 | 安装 `qrcode[pil]`，检查网络和管理员权限 |
| 扫码后一直等待或无法确认 | B 站扫码接口更新时可能出现；改用页面“手动粘贴 Cookie 登录”导入浏览器凭证 |
| 能搜索不能发送 | 检查 ffmpeg、适配器文件上限、Bilibili 播放权限 |
| 提示“操作太频繁” | 每会话限流（搜索 6 次/分钟、交付 3 次/分钟），稍等片刻即可 |
| 提示“B 站访问被暂时限制” | 插件检测到风控拦截后自动冷却，稍后自动恢复；频繁出现请登录账号或降低点播频率 |
| WebUI 不提示更新 | 确认从仓库安装，且 `metadata.yaml.version` 已递增 |
| 仍看到“调用工具”等过程文字 | 关闭 Provider 的 `show_tool_use_status` 与 `show_tool_call_result`；插件直发媒体本身不会再附带预告文字 |
| 一条消息里多个请求混在一起 | 插件会把整段拼接消息当作一个模糊关键词搜索，并强制展示候选让用户自选；若结果不对，请让用户逐条发送 |
